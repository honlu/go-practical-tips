## 可读性和可维护性

### 让`time.Duration`清晰易读

在Go中处理时间间隔时，经常需要使用`time.Duration`类型，有时候会让人难以快速理解。

一个常见的问题是：

```go
const refreshDuration = 168 * time.Hour
```

这里的`168 * time.Hour`可能并不直观，需要进行心理计算，这在快速理解和审查代码时并不理想。

一个更直观的方式是：

```go
const refreshDuration = 7 * 24 * time.Hour
```

通过将其分解为`7 * 24 * time.Hour`，可以立即清晰地看出`refreshDuration`相当于**一周**。这样，就不需要停下来计算一周的总小时数。

### 使用数字分隔符让大数字更易读

处理长数字时，代码的可读性会受到影响。

很容易忘记**多少个零**在十亿中，或者在更精确的数字（如pi）中，小数点应该放在哪里。

```go
// 不太好
const oneBillion = 1000000000
```

这可行，但一眼看过去很难确认有多少个零。现在，对比一下这个：

```go
// 更好
const oneBillion = 1_000_000_000
```
通过添加下划线，数字被分解成更易消化的块，立即清楚地表明它确实是10亿。
这个技巧不仅适用于整数：

```go
// 浮点数
const pi = 3.141_592_653_589_793 // 3.141592653589793
```

数字分隔符使你的数字更容易阅读，同时保持一切整洁有序。

### 使用注释或常量避免裸参数

当我们的IDE不支持内联提示，显示参数名称及其值时，函数参数的可读性可以得到改善。

有时，当我们使用具有多个参数的函数时，仅通过查看调用很难判断每个参数的意义，尤其是当它们具有相同的类型或为布尔值或数字等字面值时：

```go
// 不好
printInfo("foo", true, true)
```

"true"值代表什么？一个更清晰的方法是使用内联注释，直接将每个参数与其目的关联起来：

```go
// 更好
printInfo("foo", true /* isLocal */, true /* done */)

// 更好一点
printInfo("foo",
    true /* isLocal */,
    true /* done */
)
```

这使人们立即清楚每个`true`代表什么，而无需返回到函数定义。

另一种解决不清晰参数的方法是使用常量，即使它们只使用一次，并且只在该特定函数中使用：

```go
const isLocal, done = true, true
printInfo("foo", isLocal, done)

const isLocal, notDone = true, false
printInfo("foo", isLocal, notDone)
```

常量名称很重要，通过定义`isLocal`和`done`（或`notDone`）作为具有描述性名称的常量，任何人查看`printInfo`调用都可以立即理解传递了哪些`true`值。

### 空切片或，甚至更好，`nil`切片

当我们设置好要使用切片时，我们可能会想知道是使用技术上空切片还是，甚至更高效，`nil`切片。

首先，有一种方法使用`var`关键字：

```go
var t []int
```

这里，`t`是一个`int`类型的切片，但它还没有被初始化，所以它被认为是`nil`。

这意味着它不指向任何底层数组，它的长度（len）和容量（cap）都是零。

另一方面，你可以使用切片字面量初始化一个空切片：

```go
t := []int{}
```

这个切片不是`nil`。它指向一个底层数组，但这个数组没有元素。

虽然这种方法分配了一些内存来维护这个底层，但空数组，但与`nil`切片相比，内存使用差异通常很小。

所以，哪种方式被认为是惯用的？

在Go中，`nil`切片通常更受欢迎，它符合Go的简单性和有效使用零值的哲学。

1. `nil`切片不分配任何内存，它只是一个指向空地址的指针，这在高性能场景中特别有优势，因为每个效率都很重要。

2. Go社区更喜欢使用`nil`切片，因为它符合Go的简单性和有效使用零值的哲学。

3. 每条规则都有例外，例如，当处理JSON序列化时，`nil`切片在JSON中序列化为`null`，而空切片序列化为空数组（[]）。

4. 写代码时，处理`nil`切片、空切片和非空切片的方式应该类似。类似`for range`、`len()`和`append()`都优雅地处理`nil`切片，所以使用它们可以简化错误处理。
